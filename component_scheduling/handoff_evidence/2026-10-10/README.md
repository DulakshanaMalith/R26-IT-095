# Scheduling handoff screenshots and local API trace — 10 October 2026

These are genuine browser captures from the locally running Scheduling UI (`127.0.0.1:8000`), Team Formation API (`127.0.0.1:8003`) and standalone student submission portal (`127.0.0.1:8010`). The database-backed services were pointed at **isolated PostgreSQL clones** named `ipms_scheduling_evidence_20261010` and `team_formation_evidence_20261010`; the original databases were not modified for this capture. Chrome was run headlessly at desktop viewport sizes. This is a prototype demonstration, not production, institutional acceptance, or real-cohort validation.

The existing project proposal PDF was parsed in the scheduling clone and generated a 25-task `R26-IT-095` **version 7** with `UNASSIGNED` ownership. The four member IDs were explicitly entered in the UI before using Auto-Balance, which saved **version 8** with `BALANCED` ownership. The UI reported 3.5% workload CV and a 96.5% balance score for that run. Those are application outputs, not independently measured student outcomes. Opening the initial version from History did **not** restore its four member IDs automatically; entering them was necessary for a valid four-member balance demonstration. The History card also says “Research topic not recorded” for these newly generated versions, so do not cite it as evidence of topic persistence.

**Post-fix addendum, later on 10 October 2026:** the code now stores each newly generated version's member roster in `schedule_versions.team_members_json`. Two additional browser captures were taken from the separate isolated test database `ipms_scheduling_codex_test_20261010`, using synthetic group `CODEX-HISTORY-20261010` with four tasks. History restored its two saved IDs. The original 25-task screenshots above remain pre-fix historical evidence; no claim is made that their pre-fix v7 roster was retroactively recovered. Older unassigned rows without stored IDs must be confirmed manually. The background deadline checker was also corrected for object-wrapped schedules and malformed fixtures; [11 focused tests](../../Scheduling_Fresh_Integration_Test_Evidence_2026-10-10.md) passed. The local document/webhook integration test used a synthetic signed push, not GitHub.com.

Before using these in a public report, obtain approval for displaying member and panel names/IDs, crop or redact as required by the institution, and pair each image with its scope and date. Screenshots show UI states; they are not substitutes for the focused database tests or a live end-to-end student study.
